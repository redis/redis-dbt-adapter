## Findings and implementation

1. The pinned engine originally rejected the Flight transport/profile before
   any query. The patch adds a typed transport, the separate Flight library
   identity/entrypoint and client options, verified TLS roots, cookie-backed
   session initialization, and connection pool keys including session settings.
2. No-fetch query readers were dropped early. Flight cancellation can affect
   the server session, so the candidate drains and discards unused batches.
   The security probe creates a temporary relation, runs a no-fetch 100,000-row
   SELECT, then verifies its value on that connection.
3. Ordinary Arrow fields omit SQL declarations such as VARCHAR length.
   Same-session Redis information-schema lookup supplements table schemas.
   Type construction retains both exact SQL and bare type classification, with
   VARCHAR widening coverage. Upstream metadata work is
   [Redis driver #453](https://github.com/redis/redis-adbc-driver/issues/453).
4. An earlier stable optional-runtime run failed an empty Python upload with
   an explicit IO/vendor-14/40001/Unavailable publication refusal. The fix keeps
   the immutable Arrow table and creates a fresh explicit zero-row reader for
   each permitted retry. It never reuses the consumed reader. The regression
   consumes the first reader before raising the refusal, verifies a fresh
   second reader, and tests the 20-call bound and one-shot protection.
   [Project #71](https://github.com/redis/redis-dbt-adapter/issues/71) tracks it.
5. The corrected stable runtime passed parity; the later strict Rust session
   assertion exposed the timezone reset above. Qualification remains incomplete
   for stable. The successful source-main result is recorded separately.

Additional local checks: nine auth tests passed (one separate live native test

## Human review and remaining qualification

The engine's `crates/dbt-auth/AGENTS.md` requires human verification before
committing changes to accepted authentication input shapes. For this patch:

- Existing borrowed auth fields remain borrowed; option values still use Cow.
  Reading a new CA file produces owned PEM text at the I/O boundary.
- Existing get_string/get_str use and native scalar-password coercion are unchanged.
- Accepted inputs grow to include typed transport and Flight TLS/client fields;
  native Redis option mapping remains covered by its regression tests.
- The private parsed connection struct gains the selected backend. There is no
  new top-level AuthIR family; the profile schema gains the transport enum.
- The engine auth live-smoke suite in `crates/dbt-auth-tests` still needs the
  required human run/review before the patch is committed. The automated local
  integration results above do not substitute for that human requirement.

Linux execution, deterministic native Flight refused-publication injection,
same-session state/resource checks after cancellation, upstream resolution of
the stable session failure, and engine human review remain tracked in
[project #70](https://github.com/redis/redis-dbt-adapter/issues/70) and the parent
[#51](https://github.com/redis/redis-dbt-adapter/issues/51). The manual Linux
workflow is supplied but has not been run. Windows, a full taxi-through-Flight
qualification, additional Flight options/mTLS and other Flight SQL backends
are unqualified. No v2 Flight support claim or change to completed v1 support
is implied.
