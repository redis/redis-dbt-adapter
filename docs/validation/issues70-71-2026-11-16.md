## Deterministic refusal evidence

The TLS proxy uses the upstream Flight server's fault-fixture approach: replace
publication with the real workspace seal, return CAS refusal only after a
successful seal, and let the real Redis driver exhaust metadata-only rebases.
It does not forge a Flight exception or acknowledge an unexecuted seal. Authentication,
SQL execution and all other Redis responses remain real.

[Refusal receipt](issues70-71-2026-11-16/main/refusal.json):

| Path | Observed result |
| --- | --- |
| Native SQL retry | One refused workspace, nine rejected internal publication/rebase calls, then one successfully published fresh workspace; exactly one row |
| Native session state after retry | America/New_York, selected schema and temporary table value preserved |
| Native persistent refusal | Exactly 20 distinct failed statement workspaces, 180 rejected publication/rebase calls, CLI failure |
| Native statement boundary | First INSERT commits once; second INSERT exhausts 20 attempts; retained rows prove the committed prefix was not replayed |
| Optional runtime empty immutable Arrow table | First upload refused; fresh reader succeeds; resulting table has zero rows |
| Optional runtime nonempty immutable Arrow table | First upload refused; fresh input succeeds; exactly one resulting row |
| Optional runtime persistent refusal | Exactly 20 failed upload workspaces; failure surfaced |
| Optional runtime one-shot reader | Exactly one failed upload workspace; no replay |
| Owned schema cleanup | Passed |

The native commands use the compiled Rust CLI. Optional Arrow probes import the
actual engine `runtime.py` separately; they do not copy its retry implementation.
Attempt timing and per-workspace counts are retained without workspace IDs.
The engine's existing unit tests cover unknown outcomes and cancellation
classification; this fixture injects only definite refusal, never an ambiguous
write outcome.

## Cancellation evidence and limits

[Same-session receipt](issues70-71-2026-11-16/main/session-cancellation.json):
Python ADBC Flight observes one active server query lease, reads part of the
result, cancels, and receives Flight Canceled. The same connection retains
America/New_York and its temporary value 42. All newly created query leases are
inactive afterward. The resource check fails if no active lease is observed.

The native CLI SIGINT probe and fresh authenticated recovery also pass, with
[its retained diagnostic](issues70-71-2026-11-16/main/cancellation.log).
The same-session protocol probe uses Python ADBC and does not establish native
engine pool reuse after global CLI interruption. Query-lease settlement does not
measure all Search cursors, process memory, goroutines or file handles. Those
remain qualification limits, rather than inferred successes.
