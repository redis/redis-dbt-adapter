# Public auth verification and fixture restart checks, November 17, 2026

For #74, the new [public auth guide](../../v2/AUTH_VERIFICATION.md) supplies
runnable commands for the native engine under review, its dedicated backend,
separate native/Flight client configuration, expected positive/negative cases,
and a five-part impact report/human review record. The missing public
`dbt-auth-tests` crate is explicitly identified; no cloud-provider coverage or
human test execution is inferred from automated results.

The existing native CLI security probe now accepts `--transport redis` as well
as the backward-compatible Flight default. Both modes check valid auth/TLS,
rejected password and unrelated CA, password redaction, no-fetch session state,
and bounded CLI interruption/fresh recovery. The direct mode additionally
checks that explicit fields override deliberately incorrect URI credentials.
Cancellation diagnostics are checked for passwords and redacted before retention.

For #75, a saved-CA verification failure during bootstrap now returns actionable
reset instructions immediately. The already-owned fixture's verified client is
retained; no insecure recovery client is created and no marker is silently
cleared. Temporary connection failures still retry; auth/API failures retain
their original classification. Initial bootstrap remains scoped to the owned
loopback endpoint and verifies the installed CA before normal API/data use.
