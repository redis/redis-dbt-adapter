## Auth requirement review

The engine's [auth instructions](https://github.com/alberttwong/dbt/blob/3f285a37312c6ccab44a16b71d831c49e35417bd/crates/dbt-auth/AGENTS.md)
apply when modifying that crate. The merged engine PR already disclosed the
following impacts; inspection of its immutable diff confirms them:

- Existing borrowed auth fields remain borrowed. Reading the new CA file
  creates owned PEM text at the file-I/O boundary.
- Existing `get_string`/`get_str` behavior is unchanged. Native scalar-password
  coercion is preserved; Flight follows that existing scalar-password behavior.
- Accepted inputs expand with a typed `redis`/`flightsql` transport, a client CA
  file and a restricted list of non-secret Flight RPC timeout options. Flight
  requires a credential-free `grpc+tls` URI and rejects Redis server options.
- The private parsed connection config gains the selected backend. The profile
  schema gains a transport enum; no top-level AuthIR family is added.
- Normalization of existing native values is unchanged. New timeout values are
  validated as finite nonnegative numbers and passed as strings at the boundary.

The source instruction says **"Human verification is required before committing
this change."** The engine source is already committed and maintainer-merged;
this pin-only integration change introduces no additional auth semantics.
Treating that instruction as a new approval gate for every downstream pin update
was an overly broad interpretation. The recorded maintainer merge is source
acceptance evidence, not proof that a human ran a particular smoke suite.

The instructions also refer to `crates/dbt-auth-tests/README.md`, but neither
that crate nor its README exists in the merged public tree. This concrete
verification-documentation gap is tracked in
[#74](https://github.com/redis/redis-dbt-adapter/issues/74); the engine fork has
issues disabled, so the follow-up is recorded here. No human live-test execution
is claimed. Automated live native/Flight auth probes remain explicitly labeled
as automated evidence.
